# リリース前チェックリスト

自動テスト（`npm run test`、`npm run check:pii`、`npm run test:e2e`）はCIで毎回実行されるが、以下は**人間が目視で確認する**項目。特にプライバシー関連の項目は、実装ミスがそのままユーザーの信頼を損なう箇所なので、コードレビューだけでなく実機での確認を必須とする。

## 1. プライバシー確認（必須・最重要）

- [ ] ブラウザのDevTools「Network」タブを開いた状態で「自動割当」を実行し、`/auto-assign` へのリクエストPayloadを開く
  - [ ] 従業員の本名（`name`）がどこにも含まれていないこと
  - [ ] `employees` 配列の各要素が `__anonymized: true` を持っていること
  - [ ] `role`（役割、自由記述欄）も含まれていないこと（本名が書かれている可能性があるため）
- [ ] `/auto-assign` のレスポンスにも本名が含まれていないこと
- [ ] JSONエクスポート機能で保存したファイルは本名を含むため、共有PCのダウンロードフォルダに残さないよう、リリースノートやヘルプに注意書きがあること

## 2. ローカル完結機能（Lambda不要）

- [ ] 従業員の新規登録・編集・削除ができる
- [ ] シフト計画（年月）を新規作成・既存の計画を再度開ける
- [ ] シフトセルのクリック編集（勤務・有休・休、時刻）が保存される
- [ ] フィルハンドルのドラッグで行方向・列方向にシフトが一括コピーされる（PC・タブレット双方でポインタ操作を確認）
- [ ] 必要人数設定（カレンダーUIでの追加・編集・削除、一括設定）が反映される
- [ ] 希望休のチェック・保存が反映される
- [ ] 制約違反（希望休無視・連勤超過・週間労働時間超過・人員不足）がシフト表に赤枠とアラート一覧の両方で表示される
- [ ] Excel出力したファイルを実際に開き、店舗名・土日の色分け・必要人数行・合計行が正しいことを確認する（店舗名が消えていないか特に注意）
- [ ] JSONエクスポート → ブラウザをリロード（データが消えることを確認） → JSONインポートで完全復元される
- [ ] 従業員画面でテンプレートをダウンロードし、「従業員」シートを埋めて読み込むと従業員が登録される（氏名未入力行はスキップされる）
- [ ] 希望休入力画面でテンプレートをダウンロードすると、登録済みの従業員名があらかじめ入っていることを確認する
- [ ] そのテンプレートに日付を入れて読み込むと、既存の従業員名と一致する行だけチェックが入り、一致しない氏名は警告表示される（実際にデータが失われていないことを確認）
- [ ] 日付セルが文字列（`2026-09-05`）・Excelの日付型どちらでも正しく取り込まれる
- [ ] テンプレートの「使い方」シートの説明文が、誤って従業員や希望休として読み込まれていないこと

## 3. 誤操作防止

- [ ] 未保存の変更がある状態でタブを閉じよう/リロードしようとすると、ブラウザの確認ダイアログが出る
- [ ] JSON読み込み時、未保存の変更がある場合は上書き確認ダイアログが出る
- [ ] 不正なJSON（別アプリのファイル、壊れたJSON）を読み込もうとするとエラーになり、既存データは変更されない

## 4. Lambda連携（自動割当）

- [ ] 環境変数 `VITE_API_BASE_URL` が未設定の状態でも、ローカル完結機能はエラーなく使える
- [ ] 自動割当ボタンを押すと、必要人数・希望休・連勤/週間労働時間の制約を概ね満たした割当が生成される
- [ ] 既存のシフトがある状態で自動割当を実行すると、上書き確認ダイアログが出る
- [ ] Lambda呼び出しが失敗した場合（ネットワークエラー・5xx）、画面がクラッシュせずエラーメッセージが表示される
- [ ] API GatewayのUsage Plan（レート制限）が意図通り設定されていること（AWSコンソールで確認）

## 5. レスポンシブ

- [ ] タブレット幅（iPad相当）でシフト表が横スクロールしつつ操作できる
- [ ] スマートフォン幅でナビゲーション・フォーム類が崩れない
